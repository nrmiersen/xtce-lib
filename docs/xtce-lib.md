`xtce-lib` is a Python library for creating, reading, validating, and converting XTCE databases.

---

If you're here, you probably already know about XTCE. If you don't, XTCE is an XML standard for describing spacecraft command and telemetry data[^1]. An XTCE database can define data types, parameters, commands, containers, and references between them.

XTCE databases are XML documents governed by a versioned schema[^2]. Python's standard library can build and write XML, but it leaves the application responsible for constructing the right elements, attributes, namespaces, and version-specific structure.

[^1]: Read more about XTCE [here](https://www.omg.org/xtce/)
[^2]: See the XTCE specification and schema [here](https://www.omg.org/spec/XTCE)

## Why `xtce-lib`?

Here's a example of a simple XTCE 1.3 database:

??? info "TestSat-XTCE.xml"

    ```xml
    <?xml version="1.0" encoding="UTF-8"?>
    <xtce:SpaceSystem xmlns:xtce="http://www.omg.org/spec/XTCE/20250214" name="TestSat" systemType="unknown" assetType="unknown">
        <xtce:CommandMetaData>
            <xtce:ArgumentTypeSet>
                <xtce:IntegerArgumentType shortDescription="A 32-bit unsigned integer argument" name="Uint32" sizeInBits="32" signed="false">
                    <xtce:UnitSet/>
                    <xtce:IntegerDataEncoding bitOrder="mostSignificantBitFirst" byteOrder="mostSignificantByteFirst" encoding="unsigned" sizeInBits="32"/>
                </xtce:IntegerArgumentType>
            </xtce:ArgumentTypeSet>
            <xtce:MetaCommandSet>
                <xtce:MetaCommand shortDescription="Sets the battery target charge voltage" name="SetTargetVoltage" abstract="false">
                    <xtce:ArgumentList>
                        <xtce:Argument shortDescription="The target voltage to set" name="Voltage" argumentTypeRef="./Uint32"/>
                    </xtce:ArgumentList>
                </xtce:MetaCommand>
            </xtce:MetaCommandSet>
        </xtce:CommandMetaData>
    </xtce:SpaceSystem>
    ```

To demonstrate the utility of `xtce-lib`, here are a few different methods of generating this XTCE database with Python:

**With Python's `xml.etree.ElementTree`**

`ElementTree` can write the document, but you have to build the XTCE hierarchy yourself and keep the XML names and namespace straight.

```python
import xml.etree.ElementTree as ET

namespace = "http://www.omg.org/spec/XTCE/20250214"
ET.register_namespace("xtce", namespace)

def tag(name: str) -> str:
    return f"{{{namespace}}}{name}"

root = ET.Element(
    tag("SpaceSystem"),
    {"name": "TestSat", "systemType": "unknown", "assetType": "unknown"},
)
command_metadata = ET.SubElement(root, tag("CommandMetaData"))
argument_types = ET.SubElement(command_metadata, tag("ArgumentTypeSet"))
integer_argument = ET.SubElement(
    argument_types,
    tag("IntegerArgumentType"),
    {
        "name": "Uint32",
        "shortDescription": "A 32-bit unsigned integer argument",
        "sizeInBits": "32",
        "signed": "false",
    },
)
ET.SubElement(
    integer_argument,
    tag("IntegerDataEncoding"),
    {"encoding": "unsigned", "sizeInBits": "32"},
)
meta_command_set = ET.SubElement(command_metadata, tag("MetaCommandSet"))
meta_command = ET.SubElement(
    meta_command_set,
    tag("MetaCommand"),
    {
        "name": "SetTargetVoltage",
        "shortDescription": "Sets the battery target charge voltage",
        "abstract": "false",
    },
)
argument_list = ET.SubElement(meta_command, tag("ArgumentList"))
ET.SubElement(
    argument_list,
    tag("Argument"),
    {
        "name": "Voltage",
        "shortDescription": "The target voltage to set",
        "argumentTypeRef": "./Uint32",
    },
)

ET.indent(root)
ET.ElementTree(root).write(
    "TestSat-XTCE.xml", encoding="UTF-8", xml_declaration=True
)
```

The XML tree API is flexible, but it doesn't know XTCE's types or validate the document against an XTCE schema.

**With Bindings Generated by `xsdata`**

`xsdata` can generate Python dataclasses from an XTCE schema. Without `xtce-lib`, you'll need to get the [schema files](https://www.omg.org/spec/XTCE), generate the bindings you need, and keep the version-specific packages up to date yourself.

```bash
pip install "xsdata[cli]"
xsdata generate schemas/dtc-25-02-18.xsd --package generated.xtce_1_3
```

```python
from pathlib import Path

from xsdata.formats.dataclass.serializers import XmlSerializer
from xsdata.formats.dataclass.serializers.config import SerializerConfig

from generated import xtce_1_3 as xtce

space_system = xtce.SpaceSystem(name="TestSat")
space_system.command_meta_data = xtce.CommandMetaDataType(
    argument_type_set=xtce.ArgumentTypeSetType(
        choice=[
            xtce.IntegerArgumentType(
                name="Uint32",
                short_description="A 32-bit unsigned integer argument",
                choice=xtce.IntegerDataEncodingType(
                    encoding=xtce.IntegerEncodingType.UNSIGNED,
                    size_in_bits=32,
                ),
                signed=False,
            )
        ]
    ),
    meta_command_set=xtce.MetaCommandSetType(
        choice=[
            xtce.MetaCommandType(
                name="SetTargetVoltage",
                short_description="Sets the battery target charge voltage",
                argument_list=xtce.ArgumentListType(
                    argument=[
                        xtce.ArgumentType(
                            name="Voltage",
                            short_description="The target voltage to set",
                            argument_type_ref="./Uint32",
                        )
                    ]
                ),
            )
        ]
    ),
)

serializer = XmlSerializer(config=SerializerConfig(indent="    "))
Path("TestSat-XTCE.xml").write_text(
    serializer.render(
        space_system,
        ns_map={"xtce": "http://www.omg.org/spec/XTCE/20250214"},
    ),
    encoding="utf-8",
)
```

It's a solid step forward from `ElementTree`, but the API is still a bit clunky. Notice the multiple instances of having to create a set/list object (`ArgumentTypeSetType`, `ArgumentListType`)?

!!! note

    `xtce-lib` still provides these `xsdata` generated models if you'd like to use them. See [Generated Schema Models](api/generated.md).

**With `xtce-lib`**

`xtce-lib` takes the `xsdata` model structure and simplifies it.

```python
from xtce_lib import XtceDatabase, XtcePath, XtceVersion, xtce

xtcedb = XtceDatabase(name="TestSat")

xtcedb.command_metadata.argument_types.append(
    xtce.IntegerArgument(
        name="Uint32",
        short_description="A 32-bit unsigned integer argument",
        encoding_type=xtce.IntegerDataEncoding(
            encoding=xtce.IntegerEncoding.UNSIGNED,
            size_in_bits=32,
        ),
        signed=False,
    )
)
xtcedb.command_metadata.meta_commands.append(
    xtce.MetaCommand(
        name="SetTargetVoltage",
        short_description="Sets the battery target charge voltage",
        arguments=[
            xtce.Argument(
                name="Voltage",
                short_description="The target voltage to set",
                argument_type_ref=XtcePath("./Uint32"),
            )
        ],
    )
)

xtcedb.to_file("TestSat-XTCE.xml", XtceVersion.V1_3)
```

Quite a bit nicer, right? And you may have noticed the only place an XTCE version is named is in `xtcedb.to_file()`. This is because `xtce-lib`'s unified XTCE model is version-agnostic. You just define your XTCE database however you want, and let `xtce-lib` handle the version-specific formatting. Outputting with a different version is as simple as:

```python
xtcedb.to_file("TestSat-XTCE-1.1.xml", XtceVersion.V1_1)
```

??? info "TestSat-XTCE.xml, but XTCE 1.1"

    ```xml
    <?xml version="1.0" encoding="UTF-8"?>
    <xtce:SpaceSystem xmlns:xtce="http://www.omg.org/space/xtce" name="TestSat">
        <xtce:CommandMetaData>
            <xtce:ArgumentTypeSet>
                <xtce:IntegerArgumentType shortDescription="A 32-bit unsigned integer argument" name="Uint32" sizeInBits="32" signed="false">
                    <xtce:IntegerDataEncoding bitOrder="mostSignificantBitFirst" encoding="unsigned" sizeInBits="32">
                        <xtce:ByteOrderList> <!-- (1)! -->
                            <xtce:Byte byteSignificance="3"/>
                            <xtce:Byte byteSignificance="2"/>
                            <xtce:Byte byteSignificance="1"/>
                            <xtce:Byte byteSignificance="0"/>
                        </xtce:ByteOrderList>
                    </xtce:IntegerDataEncoding>
                </xtce:IntegerArgumentType>
            </xtce:ArgumentTypeSet>
            <xtce:MetaCommandSet>
                <xtce:MetaCommand shortDescription="Sets the battery target charge voltage" name="SetTargetVoltage" abstract="false">
                    <xtce:ArgumentList>
                        <xtce:Argument shortDescription="The target voltage to set" name="Voltage" argumentTypeRef="./Uint32"/>
                    </xtce:ArgumentList>
                </xtce:MetaCommand>
            </xtce:MetaCommandSet>
        </xtce:CommandMetaData>
    </xtce:SpaceSystem>
    ```

    1. Notice how `xtce-lib` automatically handled creating a byte order list, a nice little quirk of XTCE 1.1.

!!! warning "Downgrading to an older XTCE version"

    Not every model field is available in every XTCE version. For example, XTCE 1.1 doesn't have a `SpaceSystem.system_type` field. If you create a model and set `system_type` to something other than the default value, then try to output a XTCE 1.1 file, you'll get an exception. See [XTCE Version Compatibility](xtce-version-compatibility.md) for more details.

## Quickstart

### Installation

=== "pip"

    ```
    pip install xtce-lib==0.1.0a5
    ```

=== "uv"

    ```
    uv add xtce-lib==0.1.0a5
    ```

### Create a Database

First, create an `XtceDatabase`:
```python
from xtce_lib import XtceDatabase

xtcedb = XtceDatabase(name="MySatellite")  # (1)!
```

1.  > The `name` here will be the name of your root SpaceSystem.

`XtceDatabase` is your primary way to interact with the unified XTCE model.

...

### Output a File

Once you've added everything you need in the database, you can serialize it to a file:
```python
from xtce_lib import XtceVersion

xtcedb.to_file("MySatellite.xml", XtceVersion.V1_3)
```
